# Configuration reference

Generated by `npm run docs:config` from the shared editor/YAML schema. `npm run check` detects drift. Defaults can be omitted. Explicit null values are invalid. Labels and source names are literal user text, including the initial English CO₂ labels. The interface supports English and German; other locales use English labels with locale-aware dates/numbers.

Use `type: custom:tings-dashboard`. `schema_version` is always `1`; both are fixed metadata managed by the editor. Unknown properties survive round trips but do not add behavior. Array indices below use `[]` to mean each list entry.

| List | Default | Limits |
| --- | --- | --- |
| `readings` | `[]` | 0–4 entries including disabled entries |
| `calendar.sources` | `[]` | 0–16, no duplicate nonempty IDs |
| `co2.thresholds` | `[{"value":800,"color":"#c5c691","label":"Raised"},{"value":1000,"color":"#d9b36f","label":"Elevated"},{"value":1400,"color":"#db8d64","label":"High"},{"value":1800,"color":"#c96964","label":"Very high"}]` | Any count, strictly increasing values |

CO₂ maximum must exceed minimum. Calendar dismissal requires a stable unique dashboard ID when the section and selected sources are enabled. Source selection does not enable a section. Each dashboard has one appearance and one set of visibility settings. Create a second dashboard for a different presentation and let Home Assistant control switching.

Each component has an independent `features.<name>.scale` from 0.1 to 10, including arbitrary decimals; 1 preserves its original size. Scale affects text, icons and internal spacing; the readings scale applies to all readings, and the CO₂ strip scale multiplies its configured width (capped at 100% of the card). CO₂ value, status and threshold marks scale independently. Set `features.co2_value.scale` (editor: CO₂ number → Scale) to multiply the fitted number size; 0.75 makes it 25% smaller and 1.5 makes it 50% larger. Its default size fits the strip with 8px padding on each side; larger scales can clip at the strip edges. Scales multiply the existing layout clock/text/spacing settings; column allocation and card height remain controlled by layout. The clock still shrinks to fit, and the calendar still omits agenda rows that do not fit. Large scales can clip content in the fixed card area. Interactive controls keep their minimum touch sizes. Disabled components retain their scale.

See [installation](installation.md), [clock/layout](stage-1.md), [readings/CO₂/weather](stage-2.md), and [calendars and persistence](stage-3.md) for behavioral details and complete examples.
